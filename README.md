# ADVERSHIELD

**Research project:** *Adversarial Robustness Evaluation of Machine Learning-Based Intrusion Detection Systems*

ADVERSHIELD is a local web application for offline analysis of network-flow CSV datasets. It can preprocess labeled flow data, train binary intrusion classifiers, classify uploaded CSV records, run feature-space adversarial experiments, train a defended model, compare saved model results, and export reports.

> **Dataset limitation:** `dataset/raw/cicids2017_sample.csv` is synthetic demonstration data generated by this project. The full CICIDS2017 corpus is not included. Results from the sample are not benchmark results for CICIDS2017 and should not be reported as such. Upload the real dataset to evaluate it.

ADVERSHIELD does not capture packets or monitor a live network. Its attacks modify tabular flow features; they do not replay traffic or prove that every modified feature vector can occur on a real network.

## Objectives

- Compare Random Forest, XGBoost, and PyTorch MLP models for BENIGN-versus-ATTACK classification.
- Preserve the data-processing pipeline used by each saved model.
- Evaluate models on a held-out test split and report accuracy, precision, recall, F1, confusion matrix, false-positive rate, and false-negative rate.
- Study model evasion using gradient-based or black-box methods that match the model type.
- Train adversarially augmented models using training data only, then compare their clean and attacked test performance.
- Make the experiment limits and data source visible rather than presenting unsupported benchmark claims.

FGSM and PGD need a differentiable model and are available for the PyTorch MLP. Random Forest and XGBoost use black-box query attacks; transfer attacks can use an MLP surrogate. The robustness evaluator identifies when gradient attacks are being transferred through a surrogate. It does not backpropagate through tree models.

## Workflow

1. **Upload and inspect a CSV.** Use the Dataset & Training section. The dataset must contain a label column (for example `Label`) and numeric feature columns.
2. **Preprocess.** Labels are mapped to binary targets (BENIGN = 0, all other labels = 1), with original class labels retained. Identical feature rows are deduplicated and conflicting labels for identical rows are rejected. The dataset is split reproducibly; median imputation and `StandardScaler` are fitted on training records and applied to the held-out records.
3. **Train a model.** Random Forest, XGBoost, or PyTorch MLP training uses the saved training partition and reports metrics on the held-out test partition. A model's checkpoint, scaler, imputer (when present), ordered feature names, training metadata, and metrics are saved under `experiments/models/`.
4. **Classify traffic records.** Select a loadable model and upload a labeled or unlabeled CSV. The model's own saved feature order and preprocessing artifacts are applied. Confidence is shown when the estimator provides probabilities.
5. **Test adversarial robustness.** The attack simulator evaluates held-out malicious flows. FGSM/PGD are restricted to gradient-capable MLP models; query-based and transfer methods cover non-differentiable targets. Perturbations are constrained in the available feature representation. These constraints do not establish packet-level realizability.
6. **Train a defence and compare results.** Adversarial examples used for model fitting are generated from the training split only. Final clean and adversarial comparisons use a deterministic held-out test subset.
7. **Export.** Results & Defence contains model comparison, adversarial training, PDF report generation, CSV model-metric export, and settings.

Use the test split for final evaluation only. Do not select hyperparameters, features, or attack strengths based on test results and then report the same test scores as an unbiased final estimate. For stronger research evidence, use the full CICIDS2017 dataset, document the exact split protocol, and consider a separate external test set.

## Installation on Windows

Requirements: Python 3.13 (or a compatible version supported by the installed dependencies), Node.js/npm, and VS Code.

Open the project root (the folder containing this README) in VS Code. In PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd frontend
npm.cmd install
cd ..
```

If Python 3.13 is unavailable, create the environment with an installed Python version compatible with the project's packages and use that interpreter consistently. Open the project root in VS Code and select `.venv` as the Python interpreter.

The VS Code task **Start Both (ADVERSHIELD Full Stack)** starts both local services. Or open two terminals in the project root:


## Operating the five sections

1. **Dashboard** — inspect dataset label distribution, model metrics, saved experiment activity, and the latest measured worst-case robust accuracy. Values are omitted or shown as unavailable if no result exists.
2. **Dataset & Training** — use the inner Dataset tab to upload/select a CSV, inspect its dimensions and data-quality counts, choose a test split, and preprocess. Use Model Training to configure and train an architecture.
3. **Intrusion Detection** — choose a loadable model, optionally upload a traffic CSV, classify rows, inspect class/confidence output, and download the displayed predictions.
4. **Adversarial Testing** — use Attack Simulator for FGSM/PGD on MLPs or black-box methods on tree models. Use Robustness Evaluation to compare clean and adversarial held-out performance.
5. **Results & Defence** — use Model Comparison for saved metrics; Defence to train a new adversarially augmented model; Reports to generate a PDF or export model metrics to CSV; and Settings for storage information and telemetry reset.

The bundled stream shown by Intrusion Detection is a local CSV sample, not a live feed.

## Simple project explanation

ADVERSHIELD studies whether machine-learning models can identify malicious network-flow records and how their predictions change when selected numerical features are perturbed. It compares three model families, preserves each model's preprocessing steps for repeatable inference, and uses a separate held-out split to estimate clean and adversarial performance. Adversarial training augments only the training data. Because the included CSV is synthetic and adversarial changes happen in feature space, the current demonstration is an engineering prototype—not evidence of live-network protection or generalization to real CICIDS2017 traffic.

## Possible faculty viva questions

**1. What is the research problem?**  
Whether ML-based intrusion detectors remain reliable when an attacker perturbs network-flow features, and how adversarial training changes clean and adversarial performance.

**2. Why compare Random Forest, XGBoost, and MLP?**  
They represent tree ensembles and a differentiable neural network. Their different model structures also require different attack strategies.

**3. Why is the target excluded from model features?**  
Including labels as inputs would leak the answer into training and make evaluation invalid.

**4. How do you prevent preprocessing leakage?**  
Split the rows first, fit the median imputer and scaler on training rows only, and use those fitted objects to transform test rows.

**5. Why can't FGSM directly attack a Random Forest?**  
FGSM needs the gradient of a differentiable model with respect to its inputs. Tree models do not provide that gradient; use query-based or transfer attacks instead.

**6. What do FPR and FNR mean?**  
FPR is the fraction of benign records incorrectly flagged as attacks. FNR is the fraction of attack records incorrectly classified as benign.

**7. What is the attack success rate here?**  
The fraction of attack records correctly detected before perturbation that are classified as benign after the perturbation.

**8. Does adversarial training use test examples?**  
No. The generated examples are made from training records. Test examples are reserved for the final clean/adversarial evaluation.

**9. Are the current results CICIDS2017 benchmark results?**  
No. The bundled CSV is synthetic demonstration data. Benchmark claims require training/evaluating on the actual CICIDS2017 corpus and documenting the split.

**10. Does the system monitor a live network?**  
No. It analyses uploaded or bundled CSV flow records offline; it does not capture or replay packets.

**11. What is saved so inference works after a restart?**  
The checkpoint, model metadata, ordered feature names, scaler, and imputer are stored in the project. The model manifest uses project-relative artifact paths.

**12. What are the main limitations?**  
The sample is synthetic, flow identifiers are not available for related-flow splitting, feature-space perturbations are not packet-level validation, and robustness measurements depend on the chosen dataset, split, and attack settings.

## Research limitations to disclose

- No full CICIDS2017 files are bundled. Verify the source and schema of any uploaded dataset before interpreting its scores.
- The provided sample has no flow IDs/5-tuples for checking related-flow leakage. Exact feature-row duplicates are handled, but related-flow independence cannot be established from the sample.
- The constraint engine operates on tabular features. It does not enforce every cross-feature or protocol-level relationship and cannot prove an attacked vector is a valid packet/flow.
- Experiment history is restored from JSON records; in-memory alerts are not a durable audit database.
- Treat all metrics as results for the selected dataset, saved split, and configured experiment—not as guarantees for deployment.
